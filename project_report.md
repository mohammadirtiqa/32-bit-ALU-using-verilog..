# Project Report: Design and Implementation of a 32-Bit ALU Using Verilog

## 1. Introduction

An arithmetic logic unit (ALU) is a datapath component that performs arithmetic and bitwise logical operations on binary operands. It is commonly used inside a processor's execution unit. This project designs a 32-bit combinational ALU using Verilog HDL. Two 32-bit inputs and a 4-bit operation selector determine a 32-bit result and three status outputs.

## 2. Objectives

1. Design a synthesizable 32-bit ALU using Verilog-2001.
2. Implement arithmetic, logical, shift, comparison, and data-transfer operations.
3. Generate zero, carry, and signed-overflow status outputs.
4. Verify the design with a self-checking testbench and known test vectors.

## 3. Architecture and block diagram

The diagram is provided as `block_diagram.png` (easy to preview) and `block_diagram.svg` (scalable vector version). Inputs A and B enter the ALU datapath. The 4-bit control input selects the required operation. The selected result is presented at the output. Status logic derives zero from the result and reports arithmetic carry and signed overflow for ADD/SUB.

### Block descriptions

- **Operand inputs (A and B):** Two 32-bit values supplied by a processor datapath or testbench.
- **Control decoder / operation select:** The `alu_ctrl` value selects one of the 16 defined operations through a Verilog `case` statement.
- **Arithmetic unit:** Performs 32-bit addition and subtraction.
- **Logic unit:** Performs AND, OR, XOR, NOR, and NOT.
- **Shift unit:** Performs logical left, logical right, and arithmetic right shifts.
- **Compare / data unit:** Performs signed and unsigned less-than comparisons, equality, and operand pass-through.
- **Result selection:** The `case` statement routes the selected operation to the 32-bit result.
- **Status outputs:** `zero` is derived from the result. `carry` and `overflow` are defined for addition and subtraction.

## 4. Implementation

The main RTL file is `src/alu32.v`. It uses a combinational `always @*` block and assigns defaults before the `case` statement to avoid inferred latches. Addition uses a 33-bit intermediate value so the carry-out can be observed. Subtraction uses two's-complement arithmetic; the carry output is defined as no-borrow (`a >= b`). Signed overflow is calculated from operand and result sign bits.

The testbench `tb/tb_alu32.v` instantiates the ALU and uses reusable tasks to apply input vectors, wait for combinational settling, compare results and selected status flags against expected constants, and count passes and failures.

## 6. Applications

A 32-bit ALU can be used as part of:
- CPU and microprocessor execution datapaths
- Embedded-system processor cores
- FPGA-based digital systems and teaching demonstrators
- Address and index calculations
- Bit manipulation and comparison logic

This standalone design is an ALU building block, not a complete processor.

## 7. Short survey and comparison

| Approach | Typical characteristics | Comparison with this project |
|---|---|---|
| Ripple-carry adder based ALU | Simple structure and relatively low area; carry propagates through bit positions | This project uses the Verilog `+` operator. Synthesis tools choose the mapped adder architecture for the target technology. |
| Carry-lookahead / parallel-prefix ALU | Computes carries using generate/propagate logic to reduce carry delay, usually with additional wiring/area | This project prioritizes clarity and portability; it does not hand-code a fast adder. |
| Multi-cycle ALU | Reuses arithmetic hardware across cycles, reducing duplicated hardware but requiring control sequencing | This project is combinational and completes the selected operation after combinational propagation. |
| Instruction-set-specific processor ALU | Implements only operations required by a particular ISA and its control encoding | This project provides a compact educational set of 16 operations with a documented custom encoding. |

The design therefore emphasizes readability, a clear operation interface, and verification rather than claiming optimized area or timing. A fair performance comparison would require synthesis and timing reports for the same target technology and constraints.

## 8. Conclusion

A 32-bit combinational ALU was described in Verilog-2001 with 16 operation encodings and zero, carry, and overflow status outputs. A self-checking testbench supplies 18 benchmark checks covering every operation. The design can be extended with additional operations, parameterized widths, or a faster explicitly structured adder.
